# v0 — Streamlined Scope

> Status: Active
> Execution detail: `plans/v0-roadmap.md`

## 1. Goal

Enable independently running LLM instances on Kubernetes with compatible
configurations to share a common `KVCachePool`. The DRA driver auto-discovers
a compatible pool, or provisions one if none exists.

## 2. v0 — DRAM shared pools, all engines

> Note: there is no "SRAM" tier — SRAM is on-chip CPU/GPU cache and is not
> software-addressable. The host-memory tier is **DRAM**.

Scope:

- DRA driver: `kvcache.nvidia.com`.
- Cluster-scoped `KVCachePool` CRD.
- Match-or-provision behaviour (auto-discovery + auto-create when no match).
- Configurable virtual DRA slots per node. A slot is a node-level scheduling
  handle, not a node-local KV cache or a partition of pool capacity.
- Kubelet plugin injects pool endpoint + transport as env vars at bind time.
- Data plane: **DRAM** (LMCache as a K8s `Service`).
- Engines supported in v0:
  - **vLLM** — via existing LMCache KV connector.
  - **TRT-LLM** — via a custom `KvCacheConnectorScheduler` / `Worker` that
    targets LMCache (DRAM) instead of disk.
  - **SGLang** — via a thin bridge from SGLang's KV path to LMCache.

Definition of done:

- Two pods of the **same engine + same config** bind to the **same** pool
  with no manual endpoint wiring, for **each** of vLLM, TRT-LLM, SGLang.
- A repeated prompt hits the shared cache across pods.
- One minimal DeviceClass (e.g. `kvcache.nvidia.com`); full
  `KVCachePoolConfig` lives on the ResourceClaim (see README).

Out of scope for v0:

- HBM / NIXL / RDMA / NVLink transport (see v1.1+).
- Cross-engine byte interop.
- Multi-tenant isolation guarantees, KV-byte `ResourceQuota`, RBAC.
- Benchmarks at scale.

## 3. Roadmap after v0

### v1.1 — HBM for vLLM
- Use vLLM's existing NIXL KV connector.
- Small external KV index service (`block_hash → (pod, gpu, handle)`,
  lifecycle, eviction).
- DRA driver injects NIXL endpoint + transport config.
- New DeviceClass `kvcache.nvidia.com/nixl-vllm`.
- Cheapest HBM win because vLLM upstream is done.

### v1.2 — HBM for TRT-LLM
- Write a custom TRT-LLM `KvCacheConnectorScheduler` / `Worker` that uses
  NIXL/UCX instead of disk, talking to the same external index from v1.1.
- DRA driver wiring identical to v1.1.
- Easier than SGLang because TRT-LLM has a clean KV connector API.

### v1.3 — HBM for SGLang
- Ride SGLang's existing NIXL/Mooncake disaggregation path.
- Bridge SGLang's disagg endpoints to the same external index.
- Last because SGLang has no generic external KV connector API yet; the
  upstream surface is in flux.

Order rationale: vLLM → TRT-LLM → SGLang, easiest integration first.

## 4. Storage tiers — quick reference

| Tier | What it is | In project |
|------|------------|------------|
| HBM | GPU VRAM | v1.1+ via NIXL |
| DRAM | Host RAM | **v0** via LMCache |
| Disk / NVMe | Persistent | optional, not prioritised |
| SRAM | On-chip CPU/GPU cache (L1/L2) | not a tier; not addressable |

`KVCachePoolSpec.LatencyTier` enum: `HBM | DRAM | Disk`. v0 uses `DRAM`.

## 5. Architecture (v0)

```
engine pod A ──┐
               │  ResourceClaim
               │  (DRA, opaque KVCachePoolConfig)
engine pod B ──┤
               ▼
       KVCachePool (DRA, cluster-scoped)
               │  Status.Endpoint
               ▼
        LMCache Service (DRAM)
```

- Driver owns: pool discovery, pool creation, endpoint injection.
- Data plane (LMCache) owns: KV block storage, content addressing,
  eviction, dedup.
- The cluster controller selects the `KVCachePool`; every allocated slot may
  bind to that same cluster-wide pool, including slots on the same node.

## 6. Settled questions

- Driver tree: sibling repo `dra-driver-nvidia-kvcache`.
- Pool scope: cluster-scoped.
- ResourceSlice scope: node-local virtual scheduling slots; default 16 slots
  per node, configurable with `--slots-per-node`.
- DeviceClass: one minimal class; claim carries `KVCachePoolConfig`. Pool
  identity is the five compatibility fields (or an explicit `poolName`).
- Eviction, multi-tenant isolation, benchmark workload: deferred.
